# 架构决策记录: 前端 v2.5 特性补齐 (Frontend v2.5 Integration)

## 1. 背景与目标
项目中**已经存在**基于 Vue 3 + Vite + Element Plus 的 Web 前端 (`web` 目录)，且已经在 Go 后端通过 `ui.go` 使用 `go:embed` 完成了静态资源代理集成。
本次 `[TASK-4]` 的目标不是从零开始选型，而是**基于现有的前端架构及 UI 设计系统 (Dark Mode, Data-Dense Dashboard)**，补齐后端 v2.5 刚完成的 RBAC 鉴权与 Webhook 自动化部署的界面支持。

## 2. 需求深挖与对抗性审计 (Adversarial Questioning)

### 2.1 鉴权闭环 (Login & RBAC)
- 现有的 `Login.vue` 只有极少代码 (Stub)，我们需要实现真正的登录表单，调用 `/api/auth/login`。
- **自我攻击**: 如何处理页面刷新后的登录状态？
  - **决策**: 登录后将 JWT Token 持久化到 `localStorage`，并在 Axios 实例中添加请求拦截器 (Request Interceptor) 自动注入 `Authorization: Bearer <token>`。
  - **决策**: 并在 Axios 响应拦截器 (Response Interceptor) 中捕捉 401 错误，若发生则自动清理本地 token 并重定向至 `/login`。
- **角色权限隔离**: 根据返回的角色 (`admin` / `developer`)，隐藏或禁用对普通开发者不可见的功能（如服务器管理、用户管理、环境销毁等）。

### 2.2 用户管理界面 (User Management)
- **新建页面**: `UserList.vue` (位于 `Settings` 路由组下，或直接作为独立顶级路由)。
- 仅 `admin` 可访问，调用 `/api/users` 接口，支持查看当前系统所有用户及分配角色（只读/添加用户表单）。

### 2.3 Webhook 与通知显示
- 在 `ProjectList.vue` 或 `EnvironmentConfig.vue` 的界面中，暴露出当前项目/环境的 Webhook 触发 URL：`/api/webhook/github/{project_id}`。
- 提供“生成/查看 Secret” 的能力（读取 `project.WebhookSecret`），方便用户在 Github 侧配置。

## 3. 结论
完全继承并遵循项目已有的 `ui_design.md` 和 `design_system.txt` 规范（Fira/Plus Jakarta Sans，暗黑模式极简风）。在不引入新库的前提下，使用 Vue 3 + Element Plus 完成界面的补齐。
