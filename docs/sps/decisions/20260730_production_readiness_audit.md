# 决策记录 (ADR): 生产可用性与自动回滚机制 (2026-07-30)

## 1. 需求与上下文
根据与用户的确认：
- **并发要求：** 几十并发。当前 SQLite WAL + 串行化锁（项目锁、环境锁）可以满足。
- **HTTPS：** 暂不需要，可处于内网或由外部网关提供。
- **环境安全：** **绝对不污染环境，出错必须退回滚**。

## 2. 缺陷审计 (自我攻击)
- **发现问题：** 当前的 `DeployEngine.runDeploySteps` 函数中，如果 `runner.Run`（代码同步、后置脚本执行）发生错误，只会简单地将 `success = false` 并标记部署完成，**并不会自动触发回滚**。这意味着，如果代码同步成功一半、或新版本启动失败，环境将处于损坏状态。
- **性能对冲：** SQLite 设置 `SetMaxOpenConns(1)` 时，几十并发下的插入和更新可能存在微小等待，但由于事务极小，耗时不超过毫秒级，不会成为瓶颈。长耗时的 Git/SSH 操作已经被隔离到 DB 事务之外，不会阻塞 DB。

## 3. 决策与选型
为满足“保证不污染环境”：
1. **自动回滚 (Auto-Rollback)：** 在 `runDeploySteps` 启动部署时，应先查询并保存当前环境正在运行的有效版本 (如：读取上一次成功的 Deployment 记录)。
2. 若部署执行过程中 (`e.runner.Run`) 失败，则在 `defer` 或 `err != nil` 分支中拦截，触发环境的回滚，将 Symlink 切换回上一版本并执行恢复脚本。
