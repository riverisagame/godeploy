本计划详细规定了 [TASK-3] 的执行步骤。保证每次修改控制在 10-20 行代码的极简变动。

## 阶段 3.1：用户服务层实现 (User Service)
**目标**：补充缺失的用户创建能力，以便赋予开发者权限。
- **文件**：`internal/application/user_service.go` [NEW]
- **逻辑**：
  1. 定义 `UserService`，依赖 `domain.UserRepository`。
  2. 实现 `CreateUser(username, password, role string) error`。
  3. 内部使用 `golang.org/x/crypto/bcrypt` 对 `password` 进行 HASH。
  4. 插入 DB（目前 SQLite UserRepository 已经存在）。
  5. 实现 `ListUsers() ([]domain.User, error)` 供控制台查看（脱敏密码）。

## 阶段 3.2：用户接口路由绑定 (User API)
**目标**：暴露 API，并通过 RBAC 中间件限制仅 Admin 可操作。
- **文件**：`internal/interfaces/api/user_handler.go` [NEW]
- **逻辑**：
  1. 实现 `UserHandler`，依赖 `UserService`。
  2. 提供 `Create(w, r)`，解析 JSON `{"username", "password", "role"}`，默认或校验 `role` 只能为 "admin" 或 "developer"。
  3. 提供 `List(w, r)`。
- **文件**：`internal/interfaces/api/router.go` [MODIFY]
  1. 在 `NewRouter` 中初始化 `UserService`（或者直接从 `main.go` 传入，取决于构造）。
  2. 注册路由 `POST /api/users` 和 `GET /api/users`，使用 `adminProtect` 包裹。
- **文件**：`cmd/pdeploy/main.go` [MODIFY]
  1. 初始化 `UserService` 并传入 `api.NewRouter`。

## 阶段 3.3：Webhook 签名防伪与自动触发
**目标**：根据 Github Webhook Push 事件自动部署。
- **文件**：`internal/interfaces/api/webhook_handler.go` [MODIFY]
  1. 读取请求头 `X-Hub-Signature-256`。
  2. 解析 body JSON（包含 `ref` 即分支名），并且根据 URL 参数或 body 获取项目名称。为了安全和解耦，建议 URL 为 `/api/webhook/github/{project_id}`。
  3. 调用 `projectSvc.GetProject(project_id)` 获取项目及其 `WebhookSecret`。
  4. 使用 HMAC-SHA256 校验 body 数据。如果失败，返回 403。
  5. 校验通过后，遍历该项目的 Environments，找到 `branch` 匹配的环境。
  6. 调用 `deployEngine.StartDeploy(project, env, "Webhook trigger")`。

## 阶段 3.4：部署异步通知 (NotifyWebhook)
**目标**：当部署完成时，发送 HTTP POST 到指定 URL，且绝不阻塞。
- **文件**：`internal/application/deploy_engine.go` [MODIFY]
  1. 在 `runDeploySteps` 的最后（使用 defer 或最终清理阶段），判断 `env.NotifyWebhook` 是否为空。
  2. 若不为空，开启一个独立的 `go func()`。
  3. 构建 JSON Payload：`{"project": ..., "env": ..., "status": "success"/"failed"}`。
  4. 使用 `http.Client{Timeout: 5 * time.Second}` 发送 POST。失败仅记录 warning log，不影响部署状态。
