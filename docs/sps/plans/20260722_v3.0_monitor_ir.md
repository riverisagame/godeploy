# V3.0 纳米级执行计划：TASK-6 监控指标与增强型 Webhook

## 1. 目标与准则
- 接入 Prometheus metrics。
- 重构发布通知推送为带内存重试机制的异步通道。
- 增强 Webhook 接收器的平台兼容性。
- 原子化变更，严格遵循 `RED-GREEN-REFACTOR`，保证当前系统的零侵入与零破坏。

## 2. 纳米级执行步骤 (Nanoscale Execution Plan)

### 2.1 [RED 阶段] Prometheus Metrics 核心建设
- **1.** 终端执行: `go get github.com/prometheus/client_golang/prometheus` & `go get github.com/prometheus/client_golang/prometheus/promhttp`
- **2.** **创建**: `internal/application/metrics.go`
  - 初始化并注册:
    - `CounterVec` for `http_requests_total`
    - `HistogramVec` for `http_request_duration_seconds`
    - `CounterVec` for `deploy_total`
    - `Gauge` for `deploy_running_current`
    - `HistogramVec` for `deploy_duration_seconds`
- **3.** **创建测试**: 编写对上述指标操作的并发读写基础测试。

### 2.2 [RED 阶段] API 指标中间件
- **4.** **创建测试**: `internal/interfaces/api/middleware_metrics_test.go`。
- **5.** **修改**: `internal/interfaces/api/middleware.go`，增加 `MetricsMiddleware`，并在返回 `next.ServeHTTP` 后统计耗时。

### 2.3 [RED 阶段] 增强型 Webhook Dispatcher
- **6.** **创建测试**: `internal/application/webhook_dispatcher_test.go`。测试异步推送和 3 次重试失败行为。
- **7.** **创建**: `internal/application/webhook_dispatcher.go`。
  - 定义 `WebhookEvent` 结构体（包含状态、信息）。
  - 实现 `Start()` 后台消费者和 `Dispatch(url, event)`。
- **8.** **修改**: `internal/application/deploy_engine.go`。
  - 构造时注入 `WebhookDispatcher`。
  - 在发布前调 `Gauge.Inc()`，结束后 `Gauge.Dec()`；计算时长并记入 `Histogram`。
  - 使用 `Dispatcher` 推送 start, success, fail 事件替代原生 `http.Post`。

### 2.4 [RED 阶段] Webhook 接收端兼容扩展
- **9.** **修改测试**: `internal/interfaces/api/webhook_handler_test.go`，补齐 GitLab、Gitee token header 的测试用例。
- **10.** **修改**: `internal/interfaces/api/webhook_handler.go`。支持识别 `X-Gitlab-Token` / `X-Gitee-Token`。

### 2.5 [GREEN 阶段] 服务集成
- **11.** **修改**: `internal/interfaces/api/router.go`。
  - 暴露 `GET /metrics` 使用 `promhttp.Handler()`。
  - 将 `MetricsMiddleware` 加入顶层包裹。
- **12.** **修改**: `cmd/pdeploy/main.go`。
  - 注入初始化 `WebhookDispatcher`，启动后台消费并传入 `DeployEngine`。
  
## 3. 验收与回滚标准
- 验收标准：执行 `go test ./...` 应该完全通过，无并发锁死现象。
- 物理校验：向 `/metrics` 发送请求能得到正常的 Prometheus text 格式的返回。
- 重试机制应有日志可见失败退避现象。
