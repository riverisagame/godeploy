# 20260722 v2.5 前端集成 IR 纳米级计划

本计划详细规定了 `[TASK-4]` 前端 v2.5 特性补齐的执行步骤，遵循 Vue 3 + Element Plus 的设计规范与现有的极简/暗黑设计风格。

## 阶段 4.1：鉴权核心模块开发 (Auth & Login)
**目标**：完善 JWT Token 的解析与登录界面开发。
- **文件**：`web/src/utils/auth.ts` [MODIFY]
  1. 实现 `parseToken(token: string)`：将 token 使用 `atob` 解码（注意防抛错），返回 `{ username, role }`。
  2. 重写 `getUserInfo`：从 `localStorage.getItem('token')` 解析，如果不合法则返回 `null`。
  3. 重写 `isAdmin`：判断 `getUserInfo()?.role === 'admin'`。
- **文件**：`web/src/views/Login.vue` [MODIFY]
  1. 构建包含用户名和密码的 `el-form` (采用 Dark Mode 配色风格，添加 `el-card` 和标题)。
  2. 点击登录时调用 `api.login({ username, password })`。
  3. 成功后，将 `token` 存入 `localStorage`，弹出成功提示 `ElMessage`，重定向至 `/` (Dashboard)。

## 阶段 4.2：RBAC 界面适配与路由 (Layout & Router)
**目标**：基于用户角色控制主界面导航栏权限。
- **文件**：`web/src/views/Layout.vue` [MODIFY]
  1. 引入 `isAdmin` 方法。
  2. 在左侧菜单栏中，使用 `v-if="isAdmin()"` 隐藏“服务器管理”。
  3. 增加“用户管理” (`/users`) 菜单项，同样受到 `v-if="isAdmin()"` 控制，使用 `<el-icon><User /></el-icon>`。
- **文件**：`web/src/router/index.ts` [MODIFY]
  1. 在 `children` 路由配置中，新增 `/users` 路由，映射到 `UserList.vue`。
  2. *（可选）* 路由守卫增加 `meta: { requiresAdmin: true }`，对于非法访问提示 403。

## 阶段 4.3：用户管理视图 (User Management)
**目标**：仅 Admin 可见的全局用户列表及创建面板。
- **文件**：`web/src/api/index.ts` [MODIFY]
  1. 添加 `getUsers()` 接口。
  2. 添加 `createUser(data)` 接口。
- **文件**：`web/src/views/UserList.vue` [NEW]
  1. 按照 `ServerList.vue` 或 `ProjectList.vue` 的样式模板（Data-Dense Dashboard），构建 `el-table` 显示用户名、角色及创建时间。
  2. 右上角“新建用户”按钮，触发一个 `el-dialog`。
  3. 弹窗内包含 `el-form`：用户名、密码、角色 (admin/developer 的 Select)。
  4. 提交后调用 `createUser`，并刷新列表。

## 阶段 4.4：Webhook 展示面板 (Webhook Configuration)
**目标**：在项目层级展示 Webhook URL 及 Secret，以便在 GitHub/GitLab 中配置。
- **文件**：`web/src/views/ProjectList.vue` (或项目详情页) [MODIFY]
  1. 可以在展示项目环境的 Drawer / 弹出框 / 表格展开行中，增加 Webhook 信息的展示区。
  2. **逻辑**：展示项目的 `WebhookSecret`，如果为空则显示 "未配置"。
  3. **展示**：提供 Payload URL 样例：`http(s)://<你的域名>/api/webhook/github/{project.ID}`。
  4. 添加一个一键复制按钮（Copy to Clipboard）。

## 阶段 4.5：构建与后端联调测试
**目标**：编译打包前端代码，嵌入 Go 并在内存运行全量测试。
- **动作**：
  1. 在 `web/` 执行 `npm install` 与 `npm run build`。
  2. 回到 `deploy/`，运行 `go build -o pdeploy.exe ./cmd/pdeploy`。
  3. 启动 `pdeploy` 服务，手动验证前端页面登录、用户管理与 Webhook 显示是否正常。
